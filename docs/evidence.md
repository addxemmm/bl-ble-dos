# 证据、报告与结论边界

每个新运行目录还写入本地 `.gitignore`，保护自定义输出目录中的真实计划和证据不被普通 `git add` 意外加入；这不替代发布前人工检查，强制添加仍可绕过Git忽略规则。

## 四层结果分别说明什么

| 层次 | 回答的问题 | 典型证据 |
|---|---|---|
| 流程完成 | 是否执行、停止并完成清理 | supervisor事件、退出码、清理状态 |
| 协议执行 | 请求或生命周期操作是否真实发生 | 目标关联HCI、SDP/ATT响应、信道配置和断开交互 |
| 目标接收与处理 | 对端是否收到、更新属性或完成业务 | 匹配响应、目标RX/属性日志、业务完成记录 |
| 可用性与恢复 | 负载是否影响功能，何时恢复 | 独立业务基线、负载/恢复时间线、目标内部状态 |

这些层次不互相替代。程序退出`0`不是自动业务通过结论，连接超时也可能来自退出可连接模式、信号、认证条件或本机环境，不自动归因为DoS。技术路径见[协议原理](protocols.md)，已完成范围见[验证记录](validation.md)。

## 运行包

| 文件 | 记录内容 | 复核关注点 |
| --- | --- | --- |
| `plan.json` | 已校验的本次生效计划快照 | 目标、场景、适配器、限值、采集方式和输出范围 |
| `environment.json` | 系统/工具/依赖、源码哈希、新鲜适配器快照及准备耗时 | 核对实际运行代码与控制器；准备早期失败时可能缺失 |
| `events.jsonl` | supervisor 事件 | 采集就绪、worker 启停、超时、错误、中止和清理 |
| `worker.jsonl` | worker 的操作结果 | 操作次数、错误、耗时和时间线；是本机观察不是目标内部日志 |
| `result.json` | 运行结果元数据与统计 | 流程状态、采集状态、错误与 simulation 标识 |
| `host-hci.btsnoop` | `btmon` 原始 HCI 采集 | 目标/本地地址、命令及数据、连接状态与采集覆盖窗口 |
| `air.pcap` | 选择 nRF 时的 BLE 空口采集 | 是否捕获目标及相关事务、空白、漏包、加密和跟随失败 |
| `link-request-N.json` / `link-response-N.json` | 显式BLE间隔请求的内部RPC（仅启用该功能时） | 绑定的连接与helper结果；实际间隔仍核对HCI |
| `report.md` | 运行摘要与证据缺口 | simulation、范围、观察、终止原因、限制和待补证据 |
| `manifest.json` | 运行文件哈希清单 | 文件是否存在、内容是否与清单一致 |

真实运行必须先启动 `btmon` 并等待就绪，之后才启动 worker；采集异常要进入事件和终止路径，不把无采集的运行宣称为证据完整。失败或中止目录可能缺少部分产物，应保留现场并按事件解释，不填充伪造空捕获来掩盖缺失。

### 清理与未封存状态

- 采集写入进程退出**未确认**时，状态为 `cleanup_unconfirmed`，目录写入 `UNSEALED.json`，不生成 `manifest.json`。原始文件可能仍在变化，此时不是已封存证据包，`verify` 应报告清单缺失。
- 已确认进程退出、但需要强制终止时，状态为 `cleanup_forced`。可以为已停止写入的文件生成清单，但该状态不自动视作成功完成，捕获尾部及运行覆盖仍需复核。
- 磁盘或封存失败也可能生成 `UNSEALED.json`。保留目录、错误和现有文件，调查后再制作衍生记录，不补造“封存成功”状态。

离线 `demo` 是合成运行：使用显著 simulation 标识，生成演示计划、事件、报告与清单；不生成伪造 HCI 或 PCAP 文件。演示结果不应被收录为实测证据。

## 证据层级与缺口

### 主机 HCI

`btmon` 显示本机主机—控制器接口活动，有助于复核请求与连接过程。它不直接证明射频端实际送达、目标内部资源状态或其他设备通信。HCI 捕获也可能包含其他本机蓝牙会话，应减少实验背景活动并保护原件。

### BLE 空口

可选 nRF 为额外观察源，不提升为“全部空口流量”。记录是否成功跟随当前地址、是否包含建链、是否可解码及可能的漏包。HCI 与空口时钟/时间戳不应未经校准就当作严格同步；对照事务、时间窗口和实验记录解释偏差。nRF 证据不覆盖 BR/EDR。

### 外部业务探针

独立观察用户实际关心的功能，例如业务响应、心跳、服务延迟或连接维持；记录采样周期、可接受阈值、观察窗口和原始结果。它应覆盖基线、负载与恢复，而非仅负载结束后的一次“看起来正常”。当前计划中的 `external_business_probe` 只是声明，不会凭空生成业务数据。

### 外部目标系统观察

重启原因、看门狗、资源使用、故障码和相关系统日志可以帮助确认影响与恢复。记录观察接口和取证方式，避免探针本身改变目标行为。`external_ecu_observation` 是历史兼容字段，同样只是外部系统观察声明，不会自动接入日志；字段名不将工具限定为车辆用途。

## 推荐报告记录

每份用于判断可用性的报告至少应补充：

- 实验目的、目标状态与版本、拓扑、隔离条件和运行提交版本；
- 计划值与实际达成的请求速率、操作数、连接数和时间窗口；
- 业务/系统判据：失败阈值、停止条件、恢复时限及其制定依据；
- 基线、负载、恢复三阶段的独立观察和所有异常；
- 原始文件路径/哈希、时间关联方法、已知缺口与替代解释；
- 复现条件和结果适用边界，不泛化为所有控制器或所有目标设备。

项目的 `rate` 是请求操作调度速率，不是射频 PPS。一次请求可能涉及多个协议报文，重传、分片、连接事件及主机调度也会改变实际流量。没有空口计数时，不将配置的 req/s 换写为实测 PPS。

## 按协议核验有效执行

- **BR SDP**：确认成功ACL及PSM1信道，再按目标、连接生命周期、方向、信道、SDP TID匹配请求/响应。TID可跨连接重复；正常continuation不等于丢响应。
- **BR信道循环**：逐轮核对成功Connection Response、双向配置与Disconnection请求/响应。本地close不是对端确认，也不直接证明目标内部内存回收。
- **BLE读取**：Read Response可能不携带句柄，按同bearer请求顺序或解码器关联匹配，过滤反向读取、服务发现和其他连接流量。
- **BLE无响应写**：分别记录API接受、HCI发出、目标接收与业务处理；Command没有逐条ATT响应。序号可对照目标日志，最后值回读不是累计接收计数器。
- **LE连接循环**：核对每轮成功连接及断开完成；句柄可能复用，要按生命周期区间区分。单轮成功不等于连续多轮验证。
- **时间窗口**：窗口内提交、窗口内完成、窗口后有界收尾分别计数；不同主机时钟未经校准不用于精确单向延迟。
- **连接参数**：helper成功仅为requested_unverified，实际间隔以成功的HCI Connection Update事件为准。

## 唤醒等待与重试也是记录的一部分

真实TTY向导的`target_ready`保存是否启用60秒等待、实际耗时及ready/cancelled/timed_out/aborted等结果。人工确认不是连通证明；基线在确认后按原计划执行。`runtime_wall_budget_s`包含已启用的人工等待，不修改worker预算或JSON计划。环境记录还包含新鲜适配器快照时间、准备耗时、源码哈希及Git dirty状态。

`target_not_ready`表示人工等待超时且worker未启动，不表示已证实休眠；`worker_failed`应结合错误摘要、连接事件及实际提交记录判断失败阶段。只有清理明确完成、封存校验通过的普通失败才提供保留草稿返回复核页，下一次重新确认并创建新目录，不续写旧计数或覆盖旧证据。

## 完整性校验

```bash
./bt-dos verify RUN_DIR
```

清单一致时退出 `0`；清单缺失、损坏或文件校验不一致时退出 `1`。SHA-256 清单用于检查保存与传输中的内容变化，**不是数字签名**：拥有修改目录权限的人也可能一起更改文件与清单。哈希一致不证明捕获完整、来源真实、实验方案正确或业务正常。

建议保存只读原始副本；分析、筛选、去标识化与补充说明放在衍生副本中，并记录原件与衍生文件的对应关系。`report` 命令只显示已封存报告。手工补充或重新生成的报告作为衍生文件保存，不用重新计算清单掩盖未知变化。

## 数据保护

捕获可能含蓝牙地址、设备名称、服务 UUID、应用数据或配对相关材料。原始运行包默认按敏感实验资料保存，按团队策略设访问权限与保存期限。公开 issue / PR 不附原始捕获，不提交生产标识或密钥；优先提供去标识化片段或合成最小复现。去标识化后重新记录衍生文件哈希，不宣称其仍是原始证据。
